## Implementation Notes

### Sequencing (ordered)

1. **Authenticate with GitHub** — The implementer must first authenticate `gh` CLI (`gh auth login` or set `GITHUB_TOKEN`/`GH_TOKEN` env var). Without this, AC-1 (assign/label) and AC-11 (create PR) cannot be completed.
2. **Mark issue as In Progress** — `gh issue edit 2 --add-label "In Progress" --add-assignee <username>`
3. **Create the feature branch** — `git checkout -b feat/git-and-github-git-commit-helper main`
4. **Scaffold the skill** — `./scripts/new-skill.sh git-and-github git-commit-helper`
5. **Remove unwanted template files** — Delete `package.json` (this skill is Python-only). Keep `requirements.txt`. Keep the empty `tests/__init__.py`. Delete template example scripts.
6. **Write `scripts/git_commit_helper.py`** — The core Python script. Key heuristics:
   - `git diff --cached --stat` → staged file list
   - `git diff --cached` → per-file diffs (truncate each to 4KB)
   - Map file paths to conventional commit types (e.g., `feat` for new features, `fix` for bug fixes, `docs` for docs-only, `refactor`, `test`, `chore`, etc.)
   - Detect breaking changes by scanning for removed function/class definitions in known languages
   - If working tree has unstaged modifications in same paths as staged changes, print warning and refuse with exit code 1
   - Output JSON: `{"type": "feat", "scope": "...", "subject": "...", "breaking": true/false, "body": "...", "raw_diff": "..."}` 
   - With `--llm` flag and `OPENAI_API_KEY` set, also run an LLM call for better message generation (mock in tests)
7. **Write `tests/test_git_commit_helper.py`** — Use `subprocess` to run the script. Create temporary git repos with `tmp_path` and subprocess `git init` for realistic diff testing. Never hit the network.
8. **Write `SKILL.md`** — Frontmatter + sections. Agent-facing instructions on when and how to load and use this skill.
9. **Write `README.md`** — Human-facing summary.
10. **Write `reference.md` (optional)** — Deep reference for the heuristic rules.
11. **Validate locally** — Both `validate-skill.py` and `pytest -q`.
12. **Commit, push, and create PR** — `git add`, `git commit -m "feat(git-and-github): add git-commit-helper skill\n\nCloses #2"`, `git push -u origin feat/git-and-github-git-commit-helper`, `gh pr create --title "feat(git-and-github): add git-commit-helper" --body-file <(echo "...")` with the PR template filled out and `Closes #2`.

### Risk controls

- Staged-diff parsing depends on `git` being available in `PATH`. The script should check availability at startup and exit with a clear error if `git` is not found.
- `git diff --cached` may produce no output (no staged changes). This is a valid failure path and must be tested.
- Large diffs are truncated to 4KB per file to avoid overwhelming the heuristic. Document this limit.
- The `--llm` flag: stubs must be used in tests. The test must never call a real LLM API.
